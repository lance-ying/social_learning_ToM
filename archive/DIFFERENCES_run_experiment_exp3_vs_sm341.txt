WHY THE CACHE EXISTS:

The planner cache (defined in src/utils.jl, lines 5-22) is a performance optimization
that caches A* planner results for pathfinding queries. Here's why it's necessary:

1. COMPUTATIONAL COMPLEXITY:
   - The Q-value computation (Section 6) requires computing expected costs for
     multiple goal/state combinations
   - For each combination, estimate_self_exploration_cost() is called, which
     computes paths to multiple wizard locations
   - Each path computation using A* planner is expensive (O(b^d) where b=branching
     factor, d=depth)
   - Without caching, the same path queries would be recomputed thousands of times

2. CACHE KEY STRUCTURE:
   - Cache key: (agent_x, agent_y, goal_x, goal_y) - a tuple of 4 integers
   - This represents: "path from agent position (x,y) to goal position (x,y)"
   - Many goal/state combinations share the same agent positions and wizard locations,
     so the same paths are needed repeatedly

3. CACHE USAGE IN estimate_self_exploration_cost():
   - Lines 155-167 in src/utils.jl: get_cached_plan() function
   - Checks if path from (agent_x, agent_y) to (goal_x, goal_y) is cached
   - If cached: returns immediately (cache hit)
   - If not cached: computes path, stores in cache, returns (cache miss)
   - This function is called multiple times per Q-value computation:
     * Once per wizard location (lines 191, 233)
     * Once per goal/state combination
     * Once per agent (agent2 and agent3)
     * Once per timestep

4. PERFORMANCE IMPACT:
   - Without cache: Each Q-value computation could take minutes
   - With cache: Typical hit rates of 60-80% dramatically reduce computation time
   - Cache is cleared between scenarios (line 76) to prevent memory issues and
     ensure correctness (different scenarios may have different map layouts)

5. RELATION TO THEORETICAL FRAMEWORK (2507.09409v1.pdf):
   - The paper describes a theory of mind (ToM) model where an observer agent
     must decide when to observe other agents to learn about hidden state
   - The Q-value computation implements the expected value of information (EVI)
     calculation from the paper
   - The cache is a practical implementation detail that makes the EVI computation
     tractable by avoiding redundant pathfinding computations
   - The theoretical model doesn't specify implementation details like caching,
     but the cache is essential for making the model computationally feasible

RELATION TO PDF DOCUMENT (2507.09409v1.pdf):

The code implements the theoretical framework described in the paper as follows:

1. THEORETICAL MODEL (from PDF):
   - Observer agent (agent1) has uncertainty about:
     * Other agents' goals (goal inference)
     * Hidden state (wizard colors - which wizards are blue vs red)
   - Observer must decide: observe other agents or explore independently?
   - Decision based on expected value of information (EVI)

2. IMPLEMENTATION IN CODE:
   - Goal inference: goal_probs_conditioned_dict stores P(goal | observations)
   - State inference: state_probs_conditioned_dict stores P(wizard_color | observations)
   - EVI computation: Q-value computation (Section 6) computes:
     Q_observe = E[cost | observe] = Σ P(goal, state) * cost(goal, state)
     Q_not_observe = cost of exploring without observing
   - Decision: argmin(Q_observe_agent2, Q_observe_agent3, Q_not_observe)

3. KEY DIFFERENCES FROM PDF TO CODE:
   - PDF: Theoretical framework with ideal Bayesian inference
   - Code: Practical implementation with:
     * Particle filtering for inference (approximate Bayesian inference)
     * Caching for performance (makes computation tractable)
     * Convergence checks (T timestep) to handle uncertainty
     * Compatibility checks to ensure consistency

4. BUGS FIXED RELATE TO THEORETICAL CORRECTNESS:
   - Wizard candidate updating bug (Section 8): The code was incorrectly computing
     marginal probabilities P(wizard_color | observations). The fix ensures the
     code correctly implements the Bayesian update from the paper.
   - Timestep handling bug (Section 4): The code was using wrong timesteps for
     unobserved agents. The fix ensures the code correctly uses prior beliefs
     (P(goal, state | no observations)) as specified in the theoretical model.
   - Agent1 needs wizards check (Section 2): The theoretical model assumes the
     observer has a goal that requires learning about hidden state. If agent1's
     goal doesn't require blue wizards, observing is irrelevant to the model.

5. CACHE AND THEORETICAL MODEL:
   - The cache doesn't change the theoretical model - it's purely an optimization
   - The cache ensures that the EVI computation (which the paper describes) can
     be computed efficiently
   - Without the cache, the computation would be too slow to be practical, but
     the theoretical results would be the same (just slower)
